# 加载体验、儿童首页与抽福玩法设计

## 目标

在不破坏现有 AR 识别、贴面信息跟随和 3D 分子模型的前提下，完成三项增强：

1. 在弱网络下为用户提供真实、可理解的加载进度反馈。
2. 将首页改成面向日本小学生的轻量、明亮、易操作的教具入口。
3. 增加“抽福”玩法：孩子将八面体随手滚动或放置后，把朝上的一面对准摄像头，识别氨基酸并显示固定的“分子星座”寓意与学习提示。

## 已确认的产品规则

- 首页最大入口是 `カメラでスキャンする`。
- `抽福をはじめる` 和 `アミノ酸をみる` 是次级入口。
- 抽福内容采用趣味 + 学习提示的组合，而不是纯占卜。
- 每种氨基酸永久绑定一份抽福内容，不随日期、次数或设备变化。
- 普通扫描模式不显示运势，只有从抽福入口进入时显示抽福卡片。
- “分子星座”是由真实分子结构抽象出来的教学隐喻，不冒充现实天文学正式星座。
- 使用鼓励式日语，不出现“凶”“失败”“坏运气”等绝对负面判断。

## 用户流程

### 普通扫描

首页 → `カメラでスキャンする` → 摄像头识别 → 现有氨基酸学习卡与 3D 分子模型。

### 抽福扫描

首页 → `抽福をはじめる` → 显示滚动/放置提示 → 对准朝上的面 → 使用现有多帧识别确认 → 锁定识别结果 → 显示氨基酸、分子星座、固定抽福内容和学习卡。

抽福结果页提供：

- `分子をくわしく見る`：展开现有 3D 分子与学习内容。
- `もう一度抽福`：回到抽福取景状态。
- `ホームへ`：回到首页。

识别失败时保持当前取景状态，显示短提示，例如 `もう少し近づけてね`，不跳转、不清空正在显示的稳定结果。

## 加载体验

### 轻量启动壳

HTML、基础 CSS 和首页文案先渲染；OpenCV、Three.js 和识别参考资源不得阻塞首屏可见内容。

### 四阶段进度

| 阶段 | 日文显示 | 资源范围 |
|---|---|---|
| 1 | `ページを準備中` | 页面壳、字体、基础样式 |
| 2 | `図案を準備中` | 20 张参考图及必要图片 |
| 3 | `分子を準備中` | 本地分子数据、3D 组件入口 |
| 4 | `カメラを準備中` | OpenCV 与相机能力检测 |

进度必须由真实资源状态驱动；不允许用固定定时器假装完成。进度组件需要显示当前百分比、阶段名称和可继续使用的状态。大型模块继续懒加载：只有开始扫描或打开 3D 学习卡时才加载对应运行时代码。

如果某个可选模块失败，显示 `あとで試す` 或对应的友好提示，首页和不依赖该模块的资料浏览仍可使用。

## 首页视觉

- 浅色、明亮、低装饰的儿童教具风格。
- 主色组合为珊瑚橙、薄荷绿、天空蓝和暖黄色，避免深色科技风和单一渐变。
- 中心视觉使用抽象分子星图，不使用复杂写实插画。
- 扫描按钮最大，抽福与资料入口作为两个清晰次按钮。
- 所有文本使用日本小学生可读的短句；按钮高度、间距与字号优先适配手机触控。
- 首页不提前创建 3D 场景，不绘制 OpenCV 参考特征，保持首屏轻量。

## 抽福数据模型

每个 `AminoAcidId` 对应一个本地、静态的抽福条目：

```ts
type FortuneEntry = {
  constellationName: string;
  constellationTitle: string;
  meaning: string;
  fortune: string;
  tryToday: string;
  takeCare: string;
  moleculeHint: string;
  stars: Array<{ x: number; y: number }>;
  links: Array<[number, number]>;
};
```

`stars` 与 `links` 从对应分子结构生成并手工校正到适合手机显示的简洁布局；它们只用于星座视觉。真实化学结构仍由现有 `MOLECULES` 数据和 3D 查看器提供。

示例文案：

```ts
{
  constellationName: "トリプトファン座",
  constellationTitle: "きらめきの星",
  meaning: "つながりを見つける力",
  fortune: "今日は、気づいたことを一つ伝えるといい日。",
  tryToday: "分子の輪を数えてみよう",
  takeCare: "急いで答えを決めない",
  moleculeHint: "輪の形を二つ持つ分子だよ。",
}
```

结果卡必须明确标注学习语境，例如 `分子星座` 或 `学習用のイメージ`，避免把寓意误解为科学结论。

## 模块边界

- `app/lib/loadingProgress.ts`：定义加载阶段、进度合并和失败状态的纯逻辑。
- `app/data/fortunes.ts`：20 种氨基酸的固定抽福数据与分子星座点线。
- `app/AminoAcidScanner.tsx`：区分普通扫描与抽福模式，负责入口、状态与结果展示；复用现有识别生命周期。
- `app/components/LoadingScreen.tsx`：轻量加载界面，不引入 Three 或 OpenCV。
- `app/components/FortuneCard.tsx`：抽福结果卡，显示星座寓意和学习提示。
- `app/globals.css`：首页、加载和抽福卡的响应式视觉样式。

## 性能与错误边界

- 首屏只加载文本、CSS、必要的参考图索引和首页视觉资源。
- OpenCV、Three.js、分子特征和相机访问保持现有懒加载路径。
- 抽福模式只改变结果展示与入口文案，不复制识别循环、不创建第二个摄像头流。
- 识别、3D 加载或网络资源失败时，各模块分别显示错误，不让一个模块阻塞其他模块。
- 既有“锁定后只追踪一个目标”和 AnchorSmoother 行为保持不变。

## 验收标准

1. 在慢速网络模拟下，首页先于 OpenCV/Three.js 显示，并能看到真实阶段与百分比变化。
2. 首页最大按钮为 `カメラでスキャンする`，手机端无文字溢出或按钮重排。
3. 普通扫描结果不显示抽福运势；抽福扫描结果显示对应固定条目。
4. 20 种氨基酸均有完整的固定抽福数据、分子星座点线和日文学习提示。
5. 抽福结果可以进入现有 3D 模型，不改变模型资源和识别准确率。
6. 识别失败、资源失败和用户返回操作均有稳定状态，不出现页面卡死或反复重识别。
7. 新增纯逻辑、内容和组件测试；现有完整测试、lint、TypeScript 和 Pages 构建全部通过。
